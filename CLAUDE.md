## 1. Цель проекта
Одностраничный сайт-визитка (landing page) для IT-специалиста / разработчика:
представить человека, его навыки и проекты, дать способ связаться. Никакого бэкенда,
только статика - сайт должен легко деплоиться на GitHub Pages / Netlify / Vercel /
Cloudflare Pages бесплатно.

## 2. Технический стек
- Чистый HTML + CSS + немного vanilla JS (без сборщиков и фреймворков) - для визитки
  этого достаточно, минимальный вес, максимальная простота деплоя.
- Шрифты: Google Fonts - Space Grotesk (заголовки), IBM Plex Sans (текст), IBM Plex Mono
  (терминал-блок в хиро и теги стека).
- Один файл `index.html` (стили и скрипт внутри) - по аналогии с тем, что уже удобно
  публиковать одним файлом. При росте контента можно вынести `style.css` / `script.js`
  отдельно.

**Правило для Claude Code:** если в этом или в другом проекте нужен сайт или
приложение с классным, проработанным дизайном - использовать плагин
`frontend-design` (Claude Code). Если он ещё не установлен в текущей сессии,
сначала подключить: `/plugin marketplace add anthropics/claude-code`, затем
`/plugin install frontend-design@claude-code-plugins`.

- Фон: `#0B0D12` (почти чёрный тёплый графит)
- Поверхности карточек: `#161A23`
- Основной текст: `#E8EAF0`
- Приглушённый текст: `#8A93A6`
- Акцент №1 (основной, со свечением - кнопки/ссылки/hover): `#7C5CFF` (электрик-фиолетовый)
- Акцент №2 (точечно - терминал/код/бейдж статуса): `#4ADE80` (классический терминал-зелёный)
- Границы: полупрозрачные светлые (`rgba(232,234,240,0.10-0.18)`), не сплошные светло-серые,
  как раньше.
- По странице - едва заметный фон-паттерн (точечная сетка через `body::before`,
  CSS-radial-gradient, без изображений) и мягкие размытые акцентные «глоу»-пятна за
  хиро/контакт-блоком (`.glow-panel`).

Типографика - без изменений (решение: шрифты уже достаточно техничные для новой
эстетики, менять не нужно):
- Заголовки - Space Grotesk (геометричный, техничный характер, подходит IT-профилю)
- Текст - IBM Plex Sans
- Терминал-блок в хиро и теги стека - IBM Plex Mono (единое семейство с телом текста)

Композиция - без изменений (решение: сохранить структуру, менять только визуальный слой):
- Хиро: асимметрично - слева имя/роль/питч/кнопки, справа стилизованное окно терминала
  с «командой» вида `whoami` → вывод роли и стека. Это конкретный, не шаблонный приём,
  завязанный на профессию.
- Секции: Обо мне → Навыки (сгруппированы по категориям) → Портфолио (карточки проектов) →
  Контакты (прямой блок + mailto-форма, без фейкового бэкенда).
- Выравнивание: слева, широкие поля, на десктопе - 12-колоночная асимметричная сетка в хиро.

Анимации / «живые» элементы (лёгкий CSS + vanilla JS, без библиотек, с уважением
`prefers-reduced-motion`):
- Терминал в хиро печатает текст посимвольно (typing-эффект, мигающий курсор).
- Свечение (glow) на кнопках/карточках/ссылках контактов при наведении.
- Плавное появление секций (Обо мне/Навыки/Портфолио/Контакты) при скролле
  (`IntersectionObserver` + класс `.reveal`).
- Едва заметный фон-паттерн (точечная сетка) на уровне `body`.

Фоновые изображения (`assets/bg-hero.jpg`, `assets/bg-skills.jpg`, `assets/bg-contact.jpg`) -
**убраны из вёрстки**, заменены на CSS-эффекты (легче по весу страницы, лучше сочетаются
с неоновой эстетикой). Файлы физически остались в `assets/`, но `index.html` их больше не
использует. Портретное фото (`assets/photo.jpg`) - осталось, добавлена тёмная рамка и
лёгкое акцентное свечение вокруг.

## 9. Правило веб-поиска: Tavily vs встроенный поиск
- Ключ Tavily хранится в `.env` (`TAVILY_API_KEY`), файл в `.gitignore`, в чат
  и в документацию значение ключа не выводить.
- **Использовать Tavily** для любых задач конкурентного и рыночного анализа:
  анализ сайтов конкурентов, анализ рынка, поиск и сравнение УТП/оффера
  конкурентов, поиск сильных и слабых сторон конкурентных страниц - то есть
  везде, где нужен целенаправленный, структурированный веб-поиск по нескольким
  источникам для сравнения.
- **Использовать встроенный веб-поиск** (WebSearch/WebFetch) для всех
  остальных запросов - разовые фактические справки, проверка документации,
  чтение конкретной ссылки, общие вопросы, не связанные с анализом
  конкурентов/рынка.
